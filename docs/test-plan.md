# План проверок

## Автоматические проверки

Команды сборки для .NET 10 и запуска тестов находятся в [README](../README.md#build-and-test). Исполняемый набор возвращает `1`, если проверка не пройдена.

`powershell.exe -NoProfile -File .\tests\Test-LibusbWorkflows.ps1` проверяет сохранение лимита USB-пути, блокировку повышенного тока и возврат к 500 мА по таймеру и по команде из второго процесса. Тесты также проверяют восстановление после прерывания установки, отказ для старого файла отката и снятие фильтра в два этапа. Запустите тот же набор через `pwsh.exe` для PowerShell 7. Действия с USB и системными драйверами заменены заглушками.

- Физические экземпляры и `MI_XX` для Apple и другого USB VID/PID.
- Упакованный Windows USB hub header, разрыв соединения, смена VID/PID, укороченный ответ и флаги SuperSpeed.
- `18446744073709551263 → -353`, `18446744073709551122 → -494`, `29 → 29`, обычное отрицательное число и границы `UInt64`.
- Снимок `ioreg`, многострочный `AdapterDetails`, пропущенные поля, ложные вложенные поля и секреты в JSON/CSV.
- Отказ для снимка без пригодных полей и для нескольких узлов `AppleARMPMUCharger`.
- Точное восьмибайтовое представление тестового пакета, отказ без транспорта, отклонение неверного пакета до вызова mock.
- Dry-run остаётся `ReadOnly`, даже если PnP показывает WinUSB, а при отсутствии устройства выдаёт `Unsupported`.
- Проверка адреса SSH и отказ при аргументе, похожем на флаг SSH.

## Read-only интеграция на Windows

1. Выполните `inspect --vid 05AC --pid 12A2` и сравните USB-конфигурацию, скорость и PnP-узлы с независимым чтением Device Manager или `pnputil /enum-devices` с `/stack /services /interfaces`. Маскируйте instance IDs при публикации ручного вывода. [Синтаксис PnPUtil](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/pnputil-command-syntax)
2. С подключённым iPad выполните `probe --dry-run`. Ожидаются `dryRun=true`, `connectionStatus=not-queried` и прежние PnP-службы и конфигурация. Сразу после него повторите `inspect`.
3. Проверьте экспорт `report --format csv` и импорт сохранённого `ioreg` в двух форматах, в том числе `--input -`. Для отсутствующего VID/PID ожидается код `3`, для `probe` без `--dry-run` — `2`.
4. Для живого OpenSSH используйте ранее настроенный доступ. Убедитесь, что получены записи с UTC timestamp, что в отчёте есть только разрешённые поля и что `Ctrl+C` завершает активный `ssh.exe`.

На стенде 17 ноября 2026 года проверены поиск iPad, конфигурация `3`, High-Speed, `MI_00` и `MI_01`, совпадение снимков стека и порта до и после dry-run, CSV по USB, JSON и CSV телеметрии на синтетическом снимке, отсутствие девайса и отказы при неверной CLI-команде. Для OpenSSH проверена обработка ошибки соединения с закрытым локальным портом.

## Отдельный WinUSB probe

После Release-сборки `dotnet run --no-build -c Release --project tools/LegacyIpadCharge.GetStatusProbe -- --self-test` проверяет восемь байт стандартного запроса `GET_STATUS` без USB I/O. Для согласованного эксперимента используйте аргумент `--run-once` вместо `--self-test`. Он требует единственный запущенный `MI_01` для `05AC:12A2`, открывает Apple WinUSB-интерфейс и при успешном открытии и инициализации отправляет ровно один стандартный запрос чтения. Ожидаемый ответ — два байта. `WinUsb_Initialize` может сбрасывать политики интерфейса, поэтому проверяйте стабильность USB-подключения. [Результат первой проверки](feasibility.md#проверка-get_status)

## Фильтр GET_STATUS в Windows 11 x64 в VirtualBox

Фильтр предназначен для лабораторного эксперимента со снимком ВМ. После запроса отмены IRP ожидание зависит от нижнего USB-драйвера, поэтому при его зависании проба может не завершиться. Пользовательский ZIP включает сценарий с подписанным libusb-win32.

Исходники находятся в `tools/LegacyIpadCharge.StatusFilter`. Пакет KMDF добавляет нижний фильтр к физическому устройству `USB\VID_05AC&PID_12A2` через Extension INF. Отдельный интерфейс доступен `SYSTEM` и администраторам. IOCTL для `GET_STATUS` принимает пустой ввод и буфер ровно в два байта. Начиная с `0.1.0.2` фильтр отправляет `URB_FUNCTION_GET_STATUS_FROM_DEVICE` непосредственно нижнему USB-стеку через `IOCTL_INTERNAL_USB_SUBMIT_URB`. После трёх секунд ожидания фильтр запрашивает отмену IRP и освобождает буфер после завершения IRP. [Отправка URB](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/send-requests-to-the-usb-driver-stack)

1. Подтвердите, что гостевая Windows видит iPad на штатном стеке Apple. Создайте снимок ВМ до установки пакета.
2. В PowerShell 7 выполните `tools/LegacyIpadCharge.StatusFilter/Build-Lab.ps1`. Нужны Visual Studio C++ Build Tools, цели `WindowsKernelModeDriver10.0` и распакованные пакеты `Microsoft.Windows.WDK.x64`, `Microsoft.Windows.SDK.CPP` и `Microsoft.Windows.SDK.CPP.x64` версии `10.0.26100.6584`. Параметр `-Tools` принимает каталог с папками пакетов, каждая названа как `{id в нижнем регистре}.{версия}`. Подписанный пакет находится в `bin/lab-x64`, PDB — в `bin/wdk-x64`. Для отладочной сборки на стенде без библиотек Spectre доступен `-LabWithoutSpectreLibraries`.
3. Перенесите в `IPAD-LAB` каталог `driver`, файл `LabSigner.cer`, `IpadStatusProbe.exe` и `Install-Guest.cmd`. Запустите `Install-Guest.cmd` от имени администратора в гостевой Windows с включённым `TESTSIGNING`. Скрипт установит сертификат и INF, выведет стек устройства и откроет диагностический интерфейс в режиме `--check`.
4. Убедитесь, что после установки гостевая Windows видит iPad. Ответ `Y` на запрос подтверждения запускает один `GET_STATUS`. Файлы `Install-Guest.log` и `Get-Status.log` содержат результаты. Проверьте, что iPad остаётся доступен по USB после запроса.
5. Для отката используйте снимок ВМ до установки. Снимок возвращает состояние гостевых драйверов и хранилищ сертификатов.

### Диагностика загрузки KMDF

Для отладки `DriverEntry` в VirtualBox настройте в выключенной ВМ COM1 (`0x3f8`, IRQ 4) как сервер именованного канала `\\.\pipe\legacy-ipad-lab-kd`. В гостевой Windows сохраните копию BCD, задайте `bcdedit /dbgsettings serial debugport:1 baudrate:115200` и включите `bcdedit /debug {current} on`. Подключённый отладчик `kd` использует `-k com:pipe,port=\\.\pipe\legacy-ipad-lab-kd,resets=0,reconnect` и PDB из `bin/wdk-x64`. Поставьте отложенные точки останова `bu LegacyIpadStatus!FxDriverEntry` и `bu LegacyIpadStatus!DriverEntry`, затем подключите iPad в ВМ. Проверяйте возвращаемый `NTSTATUS` после `gu` командой `r eax`. После диагностики отключите гостевой режим отладки `bcdedit /debug {current} off` или восстановите сохранённый снимок. [Отладка гостевой Windows через COM-порт](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/attaching-to-a-virtual-machine--kernel-mode-)

## Первый опыт с зарядкой в ВМ

До аппаратного теста запишите модель платы или хаба, конкретный порт и его номинал при 5 В в режиме передачи данных. Проверьте допустимый ток кабеля и переходников. Для USB 2.0 iPad на стандартном USB-A исходный бюджет составляет 500 мА. Проверка привязки фильтра через `-CheckDevice` подтверждает доступ к iPad, а номинал порта берут из спецификации оборудования. [Проверка USB-порта](libusb-charge.md#check-the-usb-port)

Лабораторная версия `0.1.0.3` добавляет `IpadStatusProbe.exe --charge-once` для `IPAD-LAB`. Утилита открывает интерфейс фильтра с правом записи и вызывает отдельный IOCTL без параметров. Он отправляет один `URB_FUNCTION_CONTROL_TRANSFER_EX` на EP0. В пакете `40 40 00 00 F4 01 00 00` активная прибавка составляет 500 мА, в suspend прибавка нулевая по Apple MFi R9. При базовых 500 мА это до 1 А в активном режиме. `--print-charge-request` выводит восемь байт без открытия устройства. [Microsoft Learn](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usb/ns-usb-_urb_control_transfer_ex) · [Apple MFi R9, таблицы 2‑8 и 2‑9](https://www.scribd.com/document/694737660/MFiAccessoryHardwareSpecificationR9NoRestriction-875543417)

Для опыта нужен тракт питания и данных, рассчитанный минимум на 1 А при 5 В. Запишите `ioreg` и состояние USB-подключения до и после вызова. Успешное завершение URB подтверждает завершение передачи в USB-стеке. Изменение зарядки проверяют по току батареи и, при наличии проходного тестера, по току VBUS. В коротком опыте iPad 2 применил запрос в уже активной конфигурации. [Результат опыта](feasibility.md#запрос-до-1-а-и-откат)

Версия `0.1.0.4` добавляет `--probe-charge-path`. Она отправляет через тот же EP0 фиксированную команду `40 40 00 00 00 00 00 00` с нулевой прибавкой в обоих состояниях. `--print-charge-probe` выводит пакет локально. Этот опыт проверяет доставку vendor-запроса при исходном лимите тока.

## Замеры на iPad

17 ноября 2026 года `monitor` успешно прочитал iPad 2 через настроенный SSH-алиас. В режиме второго экрана по USB и без фиксации яркости за три минуты получено 9 замеров с интервалом 20 секунд. Медианный ток батареи **−469 мА**, диапазон **−532…−460 мА**. Во всех замерах `IsCharging=Yes`, адаптер распознан как `usb host` с 500 мА. Снимки PnP и USB-порта перед серией и после неё совпали. Ток VBUS и непрерывность изображения в течение серии отдельно не измерялись.

18 ноября 2026 года с 14:23 до 14:26 по Москве на передней панели ПК с MSI MPG Z890 EDGE TI WIFI проведён трёхминутный замер на штатном стеке Apple `538.0.0.0`. Windows показывала `USB(11)` на Intel xHCI. Яркость оставили на текущем уровне, её значение не зафиксировано. Получено 9 замеров с интервалом 20 секунд. Медианный ток батареи был **−51 мА**, диапазон **−54…−48 мА**. Во всех замерах iPad указывал `usb host`, 500 мА и `IsCharging=Yes`. Во всех 89 проверках сохранялось TCP-соединение клиента со службой Apple USBMUX. Ток VBUS и изображение в течение окна отдельно не проверяли. Ручные USB-запросы не выполняли.

Снимите по 3–5 минут телеметрии с интервалом 15–30 секунд на 20% и 100% яркости, с одним кабелем и без смены нагрузки. Для каждого прогона зафиксируйте нагрузку, порт, яркость, диапазон и медиану тока батареи, проценты заряда в начале и конце и температуру. Для сравнения портов повторите этот же сценарий. Сохраните ток и напряжение VBUS, если есть проходной тестер.

Для проверки работы без активного USB-клиента закройте приложения, использующие iPad по USB. На тракте, рассчитанном минимум на 1 А при 5 В, выполните 30-секундный тест и проверьте повышение лимита и возврат к исходному значению по шагам из руководства. Для длительного теста отдельно проверьте медианный ток батареи ≥ 0 мА, сохранение заряда и USB-подключения в течение 60 минут под выбранной нагрузкой. Проверка повторного подключения проводится отдельно. [Руководство по зарядке](libusb-charge.md#run-a-timed-trial)

## Проверка релизного ZIP на основном ПК

23 ноября 2026 года проверили установку и удаление подписанного libusb-win32 1.4.0.2 из релизного сценария на Windows 11 x64, сборка 26300, с iPad 2 GSM (A1396) и драйвером Apple USB 538.0.0.0. Secure Boot был включён, Memory Integrity была неактивна. SHA-256 проверенного Windows ZIP — `2BCBEB5131EDDCECC896CF74F7004C6D1C54F5504A71FD42DF3A0D1616A3453E`.

1. Экспортировали исходные пакеты Apple и libusb-win32. После снятия прежнего фильтра и переподключения подтвердили исходный стек Apple и доступ к внутреннему хранилищу iPad через Проводник.
2. Установщик из ZIP записал имя пакета в журнал и создал файл отката с совпадающим идентификатором установки. После переподключения фильтр появился в загруженном стеке, `-CheckDevice` подтвердил целевой iPad, а Проводник снова перечислил хранилище.
3. Откат по новому файлу снял привязку. После переподключения удалили пакет libusb-win32, службу, файл драйвера и журнал установки. Пакет Apple сохранился и Проводник перечислил внутреннее хранилище без фильтра.

Проверка охватила установку, доступ к данным и снятие драйвера. Команды зарядки в этом прогоне не отправлялись. Досрочный `-Restore` во время повышенного тока на физическом iPad, установка на чистую Windows и работа с Memory Integrity остаются открытыми проверками.
