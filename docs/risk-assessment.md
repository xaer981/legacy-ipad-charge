# Риски и ограничения Phase 0–1

Таблица описывает диагностическую CLI. Установку подписанного фильтра, подтверждение лимита порта и возврат к 500 мА описывает [руководство по зарядке](libusb-charge.md).

| Риск | Как ограничен сейчас |
|---|---|
| Повышенный ток, перегрев, просадка VBUS | В CLI отсутствует USB-транспорт управляющих запросов. Бинарное представление Linux-запроса проверяется в памяти через mock. |
| Помехи передаче данных через Apple USBMUX | `probe --dry-run` читает метаданные PnP. `inspect` и экспорт USB открывают только хаб с разделяемым доступом и отправляют два IOCTL чтения состояния порта. `WinUsb_Initialize` и открытия интерфейсов iPad в CLI нет. |
| Отключение или переподключение в процессе чтения | Для PnP предусмотрено до трёх попыток при изменении размера данных. Ответ хаба проверяется по статусу подключения и VID/PID. Если чтение сорвалось, поля порта остаются пустыми с причиной. Снимок может устареть, особенно при замене другим экземпляром того же VID/PID. |
| Утечка идентификаторов | Публичная схема содержит VID/PID, номера интерфейсов, GUID классов, имена драйверов и путь портов Windows ограниченного формата. Instance IDs и символические пути интерфейсов используются внутри процесса. Из iOS экспортируются известные числовые поля, флаги и два известных типа адаптера. Исходный текст, `battery-data`, SSH-адрес и stderr SSH не записываются в отчёт. |
| Неожиданные SSH-команды и длительные ожидания | Системный OpenSSH запускается из CLI без локальной оболочки, с проверкой ключа хоста и фиксированной удалённой командой. Допускается доверенная локальная конфигурация SSH, в том числе алиасы и её настройки маршрута. Клиент отключает `LocalCommand`, пробросы и переиспользование управляющего сокета. Сегмент чтения ограничен временем и объёмом. Монитор сообщает об ошибках выборок и продолжает работу. Если за всё время нет ни одной пригодной выборки, он возвращает код 1. |
| Неверная интерпретация замеров | `IsCharging`, параметры `AdapterDetails`, ток батареи и ток VBUS рассматриваются независимо. `bMaxPower=500 мА` и `self-powered` описывают USB-дескрипторы. Допустимую нагрузку проверяют по спецификации конкретного порта, кабеля и источника. |

## Условия для будущего эксперимента

Документация Microsoft указывает, что `WinUsb_Initialize` сбрасывает политики интерфейса. Apple USB Multiplexor уже использует WinUSB с фильтрами. Если второе открытие мешает передаче данных через USBMUX, это блокер для данного способа на рабочей машине. Для установочного эксперимента с фильтром потребуется отдельное разрешение и стенд с поддерживаемой подписью и HVCI. [WinUsb_Initialize](https://learn.microsoft.com/en-us/windows/win32/api/winusb/nf-winusb-winusb_initialize)

Для эксперимента с повышением тока нужны подтверждённые характеристики downstream-порта, источника и кабеля и проходной USB-тестер с передачей данных. Тестер наблюдает ток и напряжение в конкретном опыте. При отсутствии программного пути практический вариант — адаптер с отдельно рассчитанным питанием, у которого подтверждена одновременная передача данных с 30-pin iPad. [Пример требования к ПО для конкретной ревизии D-Link](https://www.dlink.com/-/media/Consumer_Products/DUB/DUB%20H7/QIG/DUB_H7_C1_QIG_v100_EU.pdf)
